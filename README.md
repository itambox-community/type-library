# type-library

Community catalogue of hardware models for [ITAMbox](https://github.com/itambox-community/itambox-webapp).
One YAML file per model, validated by CI, contributed by pull request. ITAMbox imports these files
as asset types through its bulk import.

## Layout

```text
asset-types/<Manufacturer>/<Model>.yaml   active: one file per hardware model
accessories/                              reserved, not active yet
consumables/                              reserved, not active yet
schema/generated_schema.json              copy of the schema generated by the webapp (never edited by hand)
schema/asset-type.json                    entry point for editors and CI, references the generated schema
scripts/validate.py                       the check CI runs
```

Only `asset-types/` accepts contributions at the moment.

## A complete example

`asset-types/Fairphone/Fairphone 5.yaml`:

```yaml
manufacturer: Fairphone
model: Fairphone 5
category: mobile-phones
specs:
  form_factor: phone
  operating_system_family: android
  display_size: 6.46 in
  display_resolution: 2770x1224
  memory_capacity: 8 GiB
  storage_capacity: 256 GiB
  camera_resolution: 50 MP
  battery_capacity: 16.2 Wh
  ip_rating: IP55
  wifi_standards:
    - 802_11ax
  weight: 0.212 kg
```

## Rules in short

- Required: `manufacturer`, `model`, `category`. Optional: `description`, `part_number`, `ean`, `specs`.
- The path must be `asset-types/<manufacturer>/<model>.yaml`, character for character.
- `specs` is a flat map of vocabulary keys. Unknown keys are rejected.
- Quantities use the vocabulary unit only, e.g. `57 Wh`. Not `57000 mWh`, not `0.057 kWh`.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the full guide, the category list and all spec keys.

## Validate locally

```bash
pip install -r requirements.txt
python scripts/validate.py            # every file
python scripts/validate.py "asset-types/Fairphone/Fairphone 5.yaml"
yamllint -c .yamllint.yaml .
```
